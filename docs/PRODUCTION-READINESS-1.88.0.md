# RadioCastOS 1.88.0 Production Readiness Review

## Audit summary

This review was performed against the supplied `RadioCastOS-1.87.0-AI-Programme-Studio-repack.zip` baseline. The codebase contains the desktop GUI, broadcast queue/engine, AI Programme Studio, TTS/news adapters, scheduling, telemetry and many focused regression scripts.

### Corrected in 1.88.0

1. **Stale review approval:** before this release, changing a segment script or rundown order could leave `workflow_status == "reviewed"`. Authorization now checks a SHA-256 fingerprint of the reviewed rundown and blocks if the content differs.
2. **Stale schedule snapshot:** schedule bookings now record the rundown fingerprint. Authorization checks that fingerprint before changing a pending booking to authorized, so a booking cannot silently authorize a different version of the programme.
3. **Weak audio preflight:** the studio now blocks empty and unreadable audio files, in addition to missing media and invalid duration, and accepts the `audio` or `audio_path` field.
4. **Regression protection:** runtime tests cover fingerprint stability, script/order sensitivity and booking fingerprint persistence.

## Production blockers / target-machine checks

The package has **not** been certified as production-ready merely by passing these source-level checks. Before going live, a station operator or technician must complete the following on the actual Windows broadcast PC:

- [ ] Build the Windows package with the pinned build dependencies and confirm the installer launches on a clean Windows account.
- [ ] Confirm the correct station profile, media library, secrets and settings survive a restart and backup/restore.
- [ ] Test the selected audio output device, sample rate, audio-file formats, sound-card reconnect and device-loss recovery.
- [ ] Verify the actual player-to-encoder route and listen to the off-air monitor; queue state and local player completion are not encoder proof.
- [ ] Verify stream reconnect, network interruption, power loss, application restart and recovery behavior.
- [ ] Run a minimum 24-hour supervised soak test with logs and disk-space monitoring before unattended use.
- [ ] Import a real as-run log and compare media path/item IDs and timestamps with independent encoder/station evidence.
- [ ] Confirm scheduled shows do not conflict with live presenter mode, AutoDJ, emergency override or station-specific automation rules.
- [ ] Test backup/restore of programme bookings, approved audio assets, configuration and audit logs.
- [ ] Confirm the station has a documented manual fallback path if the application, TTS, news feed, network or encoder fails.

## Operational safety boundaries

- Scheduled playout remains opt-in and requires explicit authorization.
- AI-generated text/audio must be reviewed by an operator; untrusted feed content is data, not instructions.
- Queue dispatch, local player completion and telemetry generated by this application do not independently prove transmission or listener reception.
- Do not enable unattended 24/7 operation until target-machine tests and station-specific encoder/as-run verification are complete.
